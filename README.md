# TSS AI Platform 前端

本仓库包含统一登录、平台选择、模型训练，以及数据标注平台前端。标注平台通过后端 API 保存项目、数据、任务和标注结果；仅运行前端不能代替后端、数据库与文件存储服务。

## 数据标注平台怎么使用

### 进入平台

1. 打开统一登录页面并登录。
2. 在平台选择页选择“数据标注平台”。旧版手动标注 Demo 是单独入口，不属于这里的新平台流程。
3. 左侧导航中，“我的项目”用于创建和管理项目；“任务广场”用于领取人工任务；“我的任务”用于继续已领取的任务；有标注管理员权限的账号还会看到“用户管理”。进入项目后，侧栏也会显示该项目的任务发布、结果工作台和成果快照入口。

### 创建项目并准备数据

1. 在“我的项目”创建项目，填写项目名称、说明和任务类型。创建者成为该项目需求方（项目 owner）；普通启用用户可自主创建项目，不需要管理员审批，也可以领取人工任务。
2. 当前内置任务模板包括“图片单标签分类”和“站点日能耗标注”。项目使用哪个模板，取决于创建时的任务类型；模板、输入和结果格式由前后端固定版本共同识别。
3. 在项目中先建立并保存标注规范，包括标签和标注说明。发布后使用的规范版本会固定在任务中；修改规范不会改写已经发布的任务。
4. 上传本机数据集 ZIP，等待服务端解析完成并查看导入结果，再继续发布。

当前导入约定：

- **图片分类**：上传包含 JPEG / PNG 图片的 ZIP。当前按未标注数据导入；压缩包中的已有标签不会自动成为平台标注结果。
- **站点日能耗**：ZIP 根目录需要有 `manifest.json`（包含 `datasetVersion`），数据文件位于 `sample/station_day_tasks_2k.csv`，每行对应一个站点日。当前页面明确提示完整小时/日资产和历史上下文尚未接入；请以导入预览及错误明细确认本批实际可用内容。
- 文件大小、格式和解析限制以当前服务端策略及页面返回为准。上传中断后可重新选择同一个 ZIP 续传；已有批次可以按批次编号恢复查看。

### 发布人工任务

1. 进入“确认并发布”，设置每包样本数并先生成预览，核对样本数量、包数和所用标注规范。
2. 当前首发规则为每包由 1 名标注员领取；默认每包 10 个样本，最后一包可以少于 10 个。确认预览后发布到“任务广场”。
3. 标注员在“任务广场”查看项目和工作量后领取任务包。进入“我的任务”打开领取的包，逐个样本填写并保存草稿。
4. 人工可以先保存未完成草稿，但正式提交某个包时，该包必须所有样本都已完成。可以先提交多个已完成包中的一部分；其他包未完成不会阻止提交当前完整包。提交后该包对标注员只读。
5. 标注员提交表示交回需求方，不代表答案已审核通过，也不代表整个项目已完成。

### 需求方处理结果、AI 和导出

在项目“结果工作台”中按页面导航查看结果与审核、重新标注、AI 处理、来源审核与集成、成果与导出：

- 查看人工提交或 AI 执行结果，逐条检查、修改、接受或退回；保存修改会形成新的结果版本，保留原结果和来源。
- 可以选择全部或部分样本重新发布给人工，也可以把选定范围交给可用的 AI Agent。平台提供范围预览，最终处理范围由需求方确认。
- AI 结果会显示执行状态、模型版本和服务实际提供的置信度。需求方可以设置高、中、低置信度边界并筛选结果；设阈值或 AI 执行完成都不会自动审核。没有分数的结果显示为未知，需由需求方决定如何处理。
- 来源审核与集成用于查看不同标注来源及集成建议。集成结果是建议，不会覆盖原始提交，也不会自动通过审核。
- 需求方确认选定结果后，创建成果快照，再从成果与导出页面导出。导出针对明确选择的成果快照，保留样本对应关系和结果来源；最终可用格式以页面提供的选项为准。

暂停项目会阻止继续处理；归档项目只读。已保存的结果和历史通过项目工作台查看，不应把“已交回”误认为“已确认”或“已完成”。

## 当前范围与边界

- 当前前端包含统一入口、项目/规范设置、ZIP 导入、图片与站点日任务模板、人工任务领取与包内编辑、需求方结果审核、AI 执行管理、结果集成和成果导出页面。
- 具体操作是否可用还取决于部署的后端版本、数据库迁移、用户权限、已配置的 AI Agent 和存储服务。页面显示“待接入”、权限不足或服务错误时，表示当前环境不支持该操作，不要用演示页面或本地状态推断生产数据已成功保存。
- `/#/labeling/demo` 是隔离的合成流程演示，不会调用真实项目、后端或模型。平台选择页上的旧版手动标注 Demo 也使用独立入口/服务；不要与新数据标注平台的项目混用。
- 模板不是任意格式插件市场。新增任务类型仍需提供并部署对应模板、输入解析、编辑器、结果校验和导出适配；当前模板列表以平台实际启用项为准。

## 本地开发

基于 Umi 4、TypeScript、React 和 Ant Design。需要 Node.js 20 及以上、npm，以及可访问的后端。

```bash
npm ci
npm run dev:local
```

本地代理目标通过项目根目录 `.env.local` 配置，具体变量与示例见[本地联调说明](docs/local-integration.md)。不要把个人服务器地址、账号凭据或 `.env.local` 提交到仓库。开发服务器的端口以终端输出为准。

隔离的合成标注流程可通过：

```bash
npm run dev:labeling-demo
```

之后访问 `/#/labeling/demo`。该演示使用合成数据，不能用于真实项目导入、提交、AI 调用或正式验收。

## 修改后的检查

```bash
npx max setup
npm run tsc
npm test
npm run lint:governance
npm run build
```

类型检查、测试和生产构建是不同检查，不能相互替代。`npm test` 不等于浏览器全流程验收。构建产物位于 `dist/`；不要手工修改 `node_modules/`、`.umi/` 或 `dist/`。

## 从哪里开始读代码

| 路径 | 职责 |
| --- | --- |
| `config/routes.ts` | 登录、平台选择、训练和标注页面路由 |
| `config/proxy.ts` | 本地开发代理 |
| `src/app.tsx` | 登录态初始化、请求处理和布局入口 |
| `src/access.ts` | 前端角色与按钮可见性；真正的权限检查仍由后端执行 |
| `src/pages/labeling/` | 标注平台项目、导入、任务、编辑、审核、AI 和导出页面 |
| `src/services/labeling*.ts` | 标注 API、数据类型和流程适配 |
| `docs/local-integration.md` | 本机前端连接后端的配置方法 |
| `docs/代码维护索引.md` | 页面、服务和测试的定位索引 |

## 维护约定

1. 新页面沿用“页面 → services → 后端 API”的结构，业务请求集中放在 services。
2. 前端隐藏按钮不构成权限控制；接口必须由后端逐请求授权。
3. 请求失败时展示实际错误，不以 Mock 数据冒充真实保存；权限错误、冲突和超时不能静默切换到其他写接口。
4. 环境地址通过配置注入，不在业务代码写死服务器 IP、节点名或凭据。
5. 接口和状态发生变化时，同步维护对应说明与测试。
