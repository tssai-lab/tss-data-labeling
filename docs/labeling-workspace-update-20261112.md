## 真实接口与独立预览

真实图片流程仍使用既有项目/规范、图片 ZIP 导入、任务包预览/发布、领取、草稿和整包提交接口。没有通过重新上传、编造 batchId 或隐藏错误绕过当前后端“同批次一次发布”的限制。

审核、AI、修订、任意范围再发布、集成及成果接口仍未实现。开发环境可从首页“待接入能力 · 独立流程预览”进入已有的合成工作流；能耗时序和质检也沿用独立合成数据。不会把真实项目 ID、原图或账号交给合成适配器，也不在真实请求失败后自动切换数据。

本机 `.env.local` 保留已确认的远端联调地址，显式开启 `LABELING_GAP_MOCK=true` 供前端验收；此文件被 Git 忽略。生产构建依旧强制关闭图片/时序合成流程。能耗项目的正式创建、导入和保存仍需后端完整支持；模板选择中保留禁用说明。

## 自动检查与人工验收

检查记录见 [validation.json](labeling-workspace-update-evidence/validation.json)。新增测试直接执行导航、品牌和发布组件的状态逻辑，并替换 React/UI/网络边界；不需要浏览器、真实令牌或真实数据。它们不能代替浏览器布局验收。

浏览器工具对实际页面及独立合成页面均拒绝访问，终端浏览器测试也被策略拦截。用户明确选择“先完成代码和自动检查，我手动验收页面”，所以本次没有截图，不宣称桌面/手机视觉或真实服务器业务写入已验收。

1. 打开 `http://127.0.0.1:8001/#/labeling`，检查导航、品牌、配色；点击品牌应返回平台选择。
2. 进入一个草稿，按规范、数据、预览顺序发布。没有 READY 批次时应显示具体引导；已有批次只保存在原浏览器时，可在“打开已有批次”中提供已知批次编号。
3. 生成预览后更换规范，应禁止发布旧预览；调整参数重新预览后恢复发布。
4. 在列表中检查只有草稿出现删除入口。确认框应明确“本地预览”，确认后行移除；刷新列表应恢复。
5. 进入开放项目后才显示审核和导出导航；通过首页独立预览检查待接入工作流，预览内容应始终标记为合成数据。

用户已授权创建 PR 并合并到 frontend；本次源码改动不修改后端或部署配置。
