# 图片分类前端联调

分支：`feat/songleiming-image-classification`，PR 目标 `frontend`。

## 入口和范围

平台选择页的“数据标注平台”进入 `/labeling`；原 Demo 保留 `/label-projects`。
真实接口前缀 `/api/labeling/v1`，复用统一登录 Token；请求不传 owner/actor。

已接入：身份、本人项目游标列表、项目创建/详情、分类规范创建、ZIP 校验/分片上传/完成/状态轮询/失败重试、样本分页、带授权的原图 Blob 预览。
只支持图片分类 ZIP（JPEG/PNG）；容量与分片大小以服务端为准。完整 ZIP 增量计算 SHA-256，不一次性加载整个压缩包；支持当前 HTTP 部署。

分类保存尚未实现：后端当前无 assignment、draft、submission 控制器。页面仅允许试选，禁用保存并明确提示未持久化。Label Studio 的会话与同步由后续接入负责，不能把浏览器试选结果冒充平台草稿。

## 本地联调

```powershell
npm ci
$env:DEV_API_TARGET = 'http://47.111.225.144'
npm run dev:local
```

开发代理转发 `/api/` 到上述网关；需要网关实际将 `/api/labeling/v1` 转发到标注服务。登录也走同一套 API，避免拿本地身份 Token 访问不同环境。数据库由后端连接，前端不配置数据库密码。

## 上传恢复

创建批次的幂等键在本次页面会话内保持稳定；上传异常/暂停后重新选择同一 ZIP，按服务端 receivedBytes 继续。刷新页面后，最近批次 ID 按 actor+project 保存在当前浏览器，详情 URL 也带 batch 参数。
后端尚无项目批次列表和按文件摘要查询批次接口，因此刷新后重新上传会创建新批次，不保证跨刷新断点续传；已有批次可通过 URL/编号找回、浏览或重试解析。不同浏览器需要传递批次详情 URL。未来应补项目批次列表和恢复元数据接口。

## 验收

1. 使用现有统一登录，进入新平台；创建 IMAGE_CLASSIFICATION 项目。
2. 保存分类名称与说明，刷新确认规范仍存在。
3. 上传包含 JPEG、PNG、损坏图片的 ZIP：显示上传进度、解析状态、有效数量和逐文件错误。
4. 点击图片预览；图片请求带 Bearer，Token 不进入 URL；切换图片释放旧 Blob。
5. 刷新详情 URL，确认批次和图片仍可查询；使用其他账号应无法读取该项目。
6. 网络失败显示错误；暂停后同文件在当前页面可继续；解析失败按 originalComplete 决定是否允许重试。
7. 分类试选显示未保存；保存接口接入前不能将其计为已完成验收。
8. 回归平台选择、统一登录、训练入口和原 Demo。

## 后端依赖

需对齐规范绑定、项目发布/打包、assignment 领取与样本访问、draft revision 保存和读回、最终 submission；若使用 Label Studio，接入受控会话与 editor-sync。不得凭 owner 图片预览接口推断标注员有领取权限。
