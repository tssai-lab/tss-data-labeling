## 一、用户主流程

| 阶段 | 后端状态 | 当前实现与限制 |
|---|---|---|
| 登录与进入平台 | ✅ | 标注服务逐请求向统一身份服务验证 Bearer Token，并建立标注侧 HUMAN actor；不存登录密码 |
| 创建项目与标签规范 | ✅ | 启用用户可创建项目成为 owner；创建/查看项目和版本化标签规范，模板绑定来自内置注册表 |
| 导入未标注数据 | ✅ | 支持图片 ZIP 导入；也支持原生任务、CSV 映射及站点日能耗 CSV 解析，样本和原始资源分开登记 |
| 配置并发布人工任务 | ✅ | 固定样本范围、规范和任务包；支持每包样本数与每样本领取席位 |
| 人工领取、标注、提交 | ✅ | 领取后按包工作；草稿可不完整；正式提交要求当前包所有样本均完成；提交后个人结果冻结 |
| AI 执行 | 🟡 | 后端有 Agent 注册、执行队列、租约、结果快照、置信度、失败清单和失败子集重试接口；没有据此证明某个真实模型已部署并完成质量验收 |
| 需求方核查和修订 | ✅/🟡 | 后端支持逐结果接受、修订、退回、标记待修正及审计；AI 置信度分档和范围选择也有接口。完整页面流程及真实用户业务验收需前后端联调 |
| 多轮处理与集成 | ✅/🟡 | 后端支持部分样本再次发布、结果引用和多数投票建议；集成结果不自动通过审核。各种模板/结果类型的算法适用性仍需定义 |
| 固定成果与导出 | ✅/🟡 | 后端可固定最终结果、异步生成 ZIP 导出；图片分类和能耗格式有实现。需对目标数据集实测导出内容与来源映射 |
| 生产发布 | ⚠️ | 本次未检查服务器当前部署提交、Flyway 状态、备份恢复能力或 GitHub Actions 最新结果 |

## 二、后端模块状态

### 1. 身份、项目和规范

- ✅ 统一登录身份校验、actor 映射、标注平台启用状态及标注管理员授权。
- ✅ `/me`、创建项目、本人项目列表/详情、创建标签规范版本。
- ✅ 新建项目收敛为图像标注和时序标注两类；分类、画框、时间点/区间通过项目模板配置。目录用 `creationAvailable` 区分新入口与历史契约，旧图片分类和站点日能耗绑定继续兼容。可信代码注册表不运行用户提交的远程代码。
- ✅ `TaskPluginRegistry` 按 `ID@版本` 注册导入、读取、结果/完成校验和导出；启动检查重复注册，目录返回五项能力与启用状态。
- ✅ 项目、导入批次和规范固定插件版本；历史读取检查冻结契约，输入 schema 不兼容升级明确拒绝。前端联合检查服务器能力与本地编辑器版本。
- 🟡 当前为随构建发布的可信代码插件，不提供远程可执行插件上传或热加载；格式治理仍需业务确认。

主要代码：`labeling-service/src/main/java/com/tss/labeling/identity/`、`project/`、`plugins/`。开发入口见 [24-task-plugins.md](08-task-plugins.md)。

### 2. 数据导入与样本

- ✅ 图片 ZIP 分片上传、哈希/安全校验、异步解析、固定样本 ID、分页浏览和授权读取原图。
- ✅ 原生任务 JSON、CSV 行任务/字段映射、图片及 CSV 资源引用；任务样本与输入资源分开管理。
- ✅ 能耗归档解析 `sample/station_day_tasks_2k.csv`，保留站点、日期、小时值、日值及来源定位；空小时为 null，数值 0 保留为 0，并拒绝导入已有标注列非空的数据。
- ✅ owner、领取者和可信 AI Worker 按各自权限读取结构化样本；输入携带 schema 标识和摘要。
- 🟡 完整能耗历史基线仍显示 `NOT_PROVIDED`；业务标签含义和复杂能耗判定规则尚需专家确认。单个验收数据集不能证明任意格式均能自动导入。

主要代码：`labeling-service/src/main/java/com/tss/labeling/imports/`、`tasks/TaskInputService.java`、`tasks/TaskInputController.java`。

### 3. 人工发布、领取、草稿和提交

- ✅ 按固定范围创建计划、冻结样本清单/规范并发布轮次；支持整包再次发布及显式选择样本再次发布。
- ✅ 人工任务广场、按包领取、领取席位并发约束、本人 assignment 查询和包内资源授权。
- ✅ 单样本草稿保存与读取，使用 revision/状态校验避免旧页面覆盖新结果。
- ✅ 人工可保留未完成草稿；正式提交按 assignment/包校验全部样本完成。可逐个提交已完成的包，其他包不阻塞。
- ✅ 轮次取消、占用释放和迟到写入校验；具体超时策略仍应按部署配置/业务规则验收。

主要代码：`tasks/TaskService.java`、`tasks/ResultService.java`、`tasks/TaskController.java`、`common/WorkflowStore.java`。

### 4. AI 执行

- ✅ 注册 AI Agent 元数据与能力；创建、领取、租约/心跳、取消、完成和失败执行。
- ✅ AI 按需求方固定的样本范围执行，不走人工包领取；逐样本保存结果、置信度、模型/规则版本和失败信息。
- ✅ 支持部分成功批次、固定终结快照、对符合条件的失败子集创建重试执行；终结操作支持幂等重放。
- ✅ 对置信度设置分档策略并为结果提供可查询的来源标识。
- 🟡 服务端执行契约已具备；实际模型 Worker 是否运行、模型效果、置信度是否校准以及前端展示/重试体验需要真实联调验证。本清单不把空壳 Worker 或接口存在等同于可用模型。

主要代码：`labeling-service/src/main/java/com/tss/labeling/ai/`；数据库 V9、V10、V11、V12、V13。

### 5. 需求方审核、集成和最终成果

- ✅ 提交审核、逐结果 CAS 审核、owner 修订形成新候选、接受/退回/待修正、操作原因与审计历史。
- ✅ 需求方固定结果选择范围；置信度分档阈值只用于筛选/批量处理条件，设置阈值不会自动确认结果。
- ✅ 图片分类多数投票可生成集成建议，保留输入结果来源，不覆盖个人答案、不自动审核。
- ✅ 最终成果快照固定已确认结果；支持项目完成/归档等状态管理和历史查询。
- ✅ 异步导出作业及下载授权；已注册图片分类 CSV 和能耗 JSONL 等格式，并包含必要映射/来源信息。

主要代码：`review/ReviewService.java`、`AtomicReviewService.java`、`AggregationService.java`、`OutcomeService.java`、`ExportService.java`、`ExportWorker.java`。
