## 结论

当前已实现并本地验证通用人工标注主链：项目、导入、模板配置、按范围发布、领取、草稿／完成／提交、需求方核查修订、部分重标、跨规范确认成果、多格式导出及项目完成。实现方向符合“平台公共流程＋LS 通用标注能力”。**尚不能判定完整平台已达到生产要求**：真实 AI 尚未开放；所有复杂控件组合、并发容量、故障恢复、部署构建和业务规则验收没有全部完成。

“有源码”“能配置”“测试通过”“生产验收通过”是不同结论。17 份模板是配置起点，不是17个已独立验收的行业解决方案。

## 为什么页面不像 LS 原站

编辑区域实际由前端仓库内的 LS `LabelStudio` 构造函数创建。图像、曲线、选择控件、区域面板、撤销恢复和结果序列化来自该源码。

页面外层使用我们的项目／任务包／审核业务布局。当前接入选用了 `interfaces` 中的顶部、侧栏、编辑历史和控件，且用 `customButtons: {_replace: []}` 隐藏 LS 原提交按钮，再提供平台的“保存草稿／标记完成／提交整个任务包”。这是接入选项与业务保存方式的改变，不是把 LS 绘图编辑器重写了一份。

显示差异还有：项目 XML 决定显示哪些对象和控件；中文化改变文案；Shadow DOM 隔离平台样式；平台曾添加时序范围按钮，本次已按要求移除，使用上游原生概览操作。LS 图像工具仍由原生工具栏提供。

本次把项目页改成紧凑工具栏＋步骤页签＋任务表；导入和字段映射放入侧边面板，任务可只读预览。标注页用样本选择器切换样本，把整包列表／规范详情折叠，缩短顶部以突出编辑区。没有为外观接入 LS 的另一套项目数据库。编辑器内也接入原生标注说明按钮，显示已有规范及本轮说明。

## 数据准备究竟做什么

它要回答“哪些文件只是资源，什么才是一份标注任务”。上传 ZIP 只负责传输和解析，不能凭压缩格式确定业务样本粒度。

| 输入 | LS 1.23.2 的机制 | 本平台当前做法 |
| --- | --- | --- |
| 原生任务 JSON | 读取 `data`，保存 Task；字段由 XML 的 `$字段` 引用 | 直接生成原生任务样本，关联平台 batch/sample ID，无需再映射 |
| CSV 每行一任务 | LS `FileUpload.read_tasks_list_from_csv` 将每行包装成 `{data: row}` | 支持“每行生成一个样本”；可指定 CSV 列对应的任务字段及资源／JSON 类型 |
| 一份曲线 CSV 是一个样本 | Task.data 中提供 CSV 资源 URL，TimeSeries 根据 timeColumn、Channel 等读取 | 同样支持任务 JSON 引用 CSV；授权下载后供原 LS 控件读取，不强制拆为观测行任务 |
| 多站点、多日期混在一张小时表 | 通用 CSV 逐行导入不会自动知道应按站点日分组，需要先整理任务粒度或使用自定义导入 | 提供通用分组映射：按站点＋日期分组，小时为时间列、数值为通道，每组生成一个原生任务 |
| 图片 | 文件上传或资源引用生成任务，配置绑定图片字段 | ZIP 内图片先登记资源，选择图片生成原生任务；也支持 JSON／CSV 直接引用同包图片 |

例如小时表有 `station_key,date_local,hour_local,value_kwh`：分组列选前两列，时间列选 hour_local，数值通道选 value_kwh；每个站点日生成 `data.series`，XML 用 `$series`、timeColumn 和 Channel 连接。映射是声明字段和样本粒度，不是修改测量值，也不负责定义业务标签。

一张小时表的每行直接作为任务，与“一天24点作为任务”含义不同。原始能耗数据有556,248条小时记录，本次实际生成23,177个站点日任务。ZIP只是容器，分组处理针对内部数据结构，未为“能耗 ZIP”新建公共业务模型。

图片／任务 JSON 不应被强制要求填写时序映射；现在任务表是默认页面，仅在导入侧边面板中按需要生成样本。当前上传入口以 ZIP 为主，与 LS 直接上传多种文件的交互仍有差异。

## 完整业务和接口

以下统一前缀 `/api/labeling/v1`；身份登录使用主平台 `/api/user/login`。浏览器带平台令牌调用，后端独立验证 actor、项目 owner、领取关系和状态。

| 阶段 | 前端调用 | 后端职责 |
| --- | --- | --- |
| 项目 | `POST/GET /projects`、`GET /projects/{p}` | 创建／查询项目和 owner、规范版本及状态 |
| 上传 | `POST /projects/{p}/imports`、`PUT /imports/{b}/chunks`、`POST /imports/{b}/complete` | 批次、分片续传、摘要校验、后台解析与逐项错误 |
| 查询输入 | `GET /projects/{p}/input-resources`、`/input-samples` | 分开返回引用文件和可标注样本 |
| 生成任务 | `POST /projects/{p}/input-resources/{r}/task-mapping`、`POST /projects/{p}/imports/{b}/tasks` | CSV 映射或图片任务生成，保留来源及幂等记录 |
| 类别／模板／摘要 | `GET /label-configs/task-types`、`/templates`、`/data-summary` | 开放能力、上游 YAML 目录和版本、项目全量字段和标签统计 |
| 配置校验／预览 | `POST /label-configs/validate`、`/sample-task` | 原 LS 校验及示例生成，或读取授权真实样本；示例明确标记且不成为业务任务 |
| 保存规范 | `POST /projects/{p}/spec-versions` | 冻结 XML、完成规则、模板／插件／导出能力和摘要 |
| 发布 | `POST /projects/{p}/package-plans`、`POST /package-plans/{id}/publish` | 固定选中范围和规范，创建任务包、轮次与席位 |
| 领取 | `GET /task-pool`、`POST /packages/{id}/claims` | 所有已启用角色均可领取，验证占用关系 |
| 编辑上下文 | `GET /assignments/{a}/items`、`/assignments/{a}/samples/{s}/task` | 给出规范、任务、草稿及允许展示的参考；资源另走授权 native-resources 请求 |
| 草稿／完成 | `PUT /assignments/{a}/drafts/{s}` | `explicitDone=false/true` 对应草稿／完成校验，检查 baseRevision，返回新版本 |
| 整包提交 | `POST /assignments/{a}/submissions` | 再验全包、完成状态及 revision，生成不可变提交 |
| 需求方核查 | `/submissions/{id}/review/decide`、项目 sample-reviews 等接口 | 确认／退回／修订，保留审核事件；重标重新选定样本、规范和参考发布 |
| 确认成果 | `POST /projects/{p}/final-snapshots` | 每个样本固定一份已确认结果，可按各自规范汇总 |
| 格式／导出／下载 | `GET /final-snapshots/{id}/export-formats`、`POST .../exports`、`GET /exports/{id}`、`GET .../file` | 按配置确定格式、异步调用 SDK Converter、打包资源／配置／来源清单 |
| 完成项目 | `POST /projects/{p}/complete` | 无开放执行；成果非空、审核未过期、覆盖已发布范围后完成并只读 |

存储：PostgreSQL 保存公共业务关系、XML／结果版本和审核等结构；配置文件目录保存原 ZIP、任务 JSON、图片／CSV 和导出包。浏览器 blob URL 仅用于显示授权资源，不作为正式输入存储。MinIO 当前服务主平台业务，不是这条标注文件链路的必需存储。

前端点击画框、缩放、选标签时在本地 LS 编辑器内操作，不会每次鼠标移动都发 HTTP。点击保存时序列化原生结果再请求平台 API。这种编辑器本地交互＋宿主业务保存的分层与 LS 的机制一致。

## 和 LS 原平台的逻辑差异

| 部分 | 相同机制 | 当前平台差异 |
| --- | --- | --- |
| 配置与任务 | XML → 字段 → 对象／控件 → 原生结果 | 绑定平台 UUID、冻结规范和 task.data，不接上游 Project/Task API |
| 后端请求 | 配置／预览／保存通过 HTTP | LS 原平台调用自己的 Django API；我们调用 Java API，再由 Java 调用仓库内 LS Python 模块 |
| 保存 | 结果可序列化、恢复并服务导出 | 平台分草稿、显式完成、整包提交、核查确认和成果，不能把 LS 单任务提交按钮直接当整包提交 |
| 规范变化 | 原 LS 检查已有答案与修改后的项目配置是否兼容 | 我们创建新规范，旧提交继续使用原规范；不兼容参考只读，参考不自动算完成 |
| 数据与资源 | 原生任务数据＋引用资源 | 平台批次与权限读取，限制同包本地资源；不沿用 LS 上传目录或外网自动下载 |
| 预测及历史答案 | LS 支持 annotations/predictions 结构 | 原输入可保留这些结构，但人工编辑页当前注入平台草稿和授权参考，不把导入答案自动计为完成；完整预测候选接入尚未完成 |
| 任务管理 | 项目、任务列表和编辑器协作 | 正在参照 LS 布局组织平台页面，保留本平台包、轮次、核查和成果流程 |

当前“需求方”按项目 owner 执行管理权限；代码允许已启用账号创建项目并成为 owner，没有另外按主平台某个 roleId 限制创建。若产品要求预先授予专门“需求方”资格，该创建门禁还需落实，不能把 owner 隔离说成已有该资格门禁。

## 源码到底改了什么

本次按相同提交逐文件比较纳入前端的 libs：1,739个文件内容不变，37个修改文件，另增1个工具文案文件；统计忽略行尾差异，仅针对纳入工程的依赖范围，不代表复制了整个 LS 产品。

- 图像几何控件与工具、原生结果序列化／反序列化、XML 控件装配和共享 core/ui 等主体继续使用上游源码；没有另写一套画框引擎。
- 文案：工具栏、侧栏、历史、设置、说明、TextArea 等中文化；键盘动作和结果字段不因翻译改名。
- 接入：`LabelStudio.tsx` 增加 ready、中文 locale 和容器标记；快捷键识别 Shadow DOM 的真实事件目标；弹窗放在编辑器内部；任务及历史 ID 支持字符串 UUID。
- 草稿：CustomButton/AppStore 增加 draftOnly 可选行为，草稿不推进原队列或丢弃状态，默认保留原行为。
- 时序：四个核心文件现与 LS 1.23.2 逐字节一致；此前缺测断线、概览 UTC 和额外缩放保护均已撤回，不独立修改上游行为。
- 入口和布局：`LocalEditor` 决定 interfaces、按钮和数据／答案注入，平台附加时间范围按钮已移除；这些外层代码与 LS 绘图控件修改是两回事。
- 配置页：同版 ConfigPage/模板库源码接我们的 HTTP 请求和保存，模板来源统一为后端原 YAML。
- 后端：原 LS 配置解析／示例生成、SDK LabelInterface/Converter 保留并去除框架耦合；资源清单替换上游下载路径，增加平台分阶段校验与固定成果交付。

前端来源见 `frontend/vendor/label-studio/UPSTREAM.md`，后端见 `ls-source-adapter/SOURCE.md`，本地逐文件对照记录 `.tools/ls-source-audit.json`。

## 可用任务及生产验收

计算机视觉保留12份社区预设，包括分类、框／多边形、关键点、笔刷分割、描述、OCR组合、动态标签等。时序保留活动识别、变化点、离群点／异常、信号质量、预测5份预设，基本能力是分类、时间点／区间、多通道和备注。预测模板不提供真实预测模型；高级 OCR／分割等不能仅因模板能打开就判为业务验收通过。

当前已验证：通用时序完整人工闭环、图像实际画框保存、动态／条件／区域校验用例、部分重标和跨规范成果页面下载；适用配置的六种格式在后端转换及解包验证。并未将全部视觉模板、所有控件组合及 LS 企业功能认定为同等可用。

本次真实数据：3,409,994字节原 ZIP，556,248小时行 →23,177站点日，映射73,812ms；摘要数一致，浏览器任务表约5.5—7.1秒载入；24点曲线完成分类、时间点标注、保存与刷新恢复。一次发布仍最多10,000样本，需要分批。这是单机单次结果，不是并发性能承诺。

生产前优先任务：

1. 数据管理／发布改服务端分页筛选，避免现在先收集全部23,177条再客户端分页；CSV长映射改后台任务和进度，避免同步请求接近120秒超时。
2. 明确并验收需求方资格、整包分轮、撤销／重标／跨规范和失败重试等业务权限及恢复矩阵。已有局部并发／409测试不等于目标并发容量通过。
3. 补视觉复杂组合、真实多图、长时序、浏览器兼容、资源大文件和长期编辑的系统验收；业务能耗日值／历史对照与标签口径仍需独立确认，不能用通用曲线证明已满足所有领域规则。
4. 当前编辑器构建脚本显式使用 development 模式，开发包约27MiB；生产发布前需验证生产模式、资源缓存及构建可复现性。
5. 实际 AI 执行、预测候选回写和质检尚未完成；备份恢复、日志监控、存储额度／清理与故障演练需有生产验收证据。本轮不连接服务器做这些操作。

因此：人工主业务已可在本地使用和验收；整个原目标（包含真实 AI 等）未全部完成，当前不宣布可直接生产上线。

最新布局验收：原生编辑区在1280／1700宽度均从约210px开始，无页面横向溢出；样本预览遵循所选规范，任务表可复选带入发布，专注标注页支持上下条、搜索包内样本及统一保存栏。共享 Tooltip 已修复 Shadow DOM 挂载和定位。详细记录见前端 docs/ls-workspace-layout.md。
