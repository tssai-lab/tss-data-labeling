# 通用时序输入与 LS 源码接入契约

日期：2026-11-14。状态：P0 对接草案；前端已有本地实现，后端结构化读取、校验器、插件与格式转换尚未接入。本文不声明新增 API 已可调用。

## 目标与边界

### 最新优先级：保留 LS 原生通用连接能力

用户已明确：优先保留 LS 通用编辑能力，前端保留源码，后端复用并改造其配置、输入、结果和导出处理，再接本平台业务。下面的 timeseries-input-v1 是一种可选的表格输入适配，不能成为所有 LS 任务唯一、强制的输入结构。

需要保留两条连接路径：一条是平台提供受控的 LS task.data＋冻结 XML，沿用原生变量绑定、JSON/CSV 读取、时间格式和通道能力；另一条是能耗宽表或通用表格经适配器生成可用输入。前者的授权资源解析和平台提供者仍需实现，当前前端仅完成后者，不能将新增适配器称为完整原生路径已经接通。

本地适配器的 16 通道、50000 点、%Q 时间格式、列名和分组约定只约束该适配器，不是 LS 编辑器的通用能力上限。后续接口必须用显式能力/输入配置区分它们，不能为了套用本结构而禁用上游已支持的时间格式或重命名所有原生字段。

源码核对：LS 的 Project.label_config 保存 XML，Task.data 保存数据对象/资源引用，Annotation.result 保存类型化结果。FileUpload 可以把 CSV 当任务列表，也可按文件资源形成任务；TimeSeries 前端控件通过 value 绑定从 task.data 读取 JSON 或读取 CSV 后解析。后端不把所有时序固定成站点日；导出器按解析配置、任务数据和结果工作。应移植这些通用连接能力，而不是只重写能耗处理。

下一阶段先补原生 task.data/配置/资源提供者与版本化结果连接，再扩展领域导入。领域校验只在对应任务规范启用；通用标注不自动具有能耗规则、阈值或小时桶语义。

LS 时序控件本身支持不同长度和多个通道。平台通用读取、校验和导出入口不应绑定能耗的 24 点、value_kwh、北京时间或 kWh。能耗站点日继续保留专用输入适配；其他时序使用明确的时间轴和通道描述，通过相同编辑器与公共业务流程处理。

前端分支 feat/frontend_LS；后端分支 feat/backend_LS。仅本地开发测试，不连接服务器，不推送、合并或部署。

## 输入结构

新格式：`inputFormat=timeseries-input-v1`、`schemaId=timeseries-input@1.0.0`。结构草案文件：`D:/projects/Annotation/backend/labeling-service/src/main/resources/schemas/timeseries-input-v1.schema.json`。

| 字段 | 约定 |
|---|---|
| sampleId | 正式 API 使用平台 UUID；前端小样本中的 local-series:* 只是浏览器本地标识，不直接写入服务端主键 |
| inputHash | 版本化输入摘要；当前前端小样本为规范化 payload 的 JSON 文本 SHA-256，生产端须固定跨语言序列化/摘要算法，不能未经验证直接比较各语言默认序列化结果 |
| payload.time.kind | number：显式数值时间；timestamp：Unix 毫秒绝对时间 |
| payload.time.unit | 数值轴必须声明单位；timestamp 固定 ms |
| payload.time.values | 严格递增、无重复、有限数值；支持不等间隔，不能静默排序或补点 |
| payload.channels | 1—16 个通道；column 为稳定输入字段，label 为显示名，unit 为原数据单位 |
| channel.values | 与时间数组等长，有限数值或 null；负值、零和缺测分别保留 |

当前内联小样本配置要求每条 2—50000 点；CSV 预览文件不超过 10 MiB、50000 行、500 个分组样本。这是本地预览边界，不是整个数据集容量承诺。正式大文件仍走既有 ZIP 分片和后端解析，服务端单样本容量/分片读取策略另行验收。

CSV 映射显式指定时间列、数值通道、可选样本分组列、时间类型和单位。一组形成一条样本，映射记录源列与 channel_1/channel_2 等稳定字段，保留源文件摘要与行号。ISO 日期时间必须含 Z 或偏移，规范化到 Unix 毫秒；当前编辑器绝对时间视图按 UTC 显示，不声称已按任意地区时区渲染。

## 编辑器连接

前端依据 inputFormat 分派：原能耗格式走能耗读取器；通用格式走共享时序读取器。后者提供 LS JSON 或 CSV 输入，保留真实时间值和所选通道，不能用示例值填充真实样本缺失字段。

XML 控件通过 value/timeColumn/Channel.column 连接数据，名称无需固定为 load_curve。通道必须存在，显示单位不能冒充数值单位转换。当前通用绝对时间配置使用 `timeFormat="%Q"`；数值轴不设 timeFormat。其他时间格式须新增经过验证的转换，不能静默套用。

项目“按当前时序字段生成配置”提供一个可编辑起点，随后仍使用 LS 原生可视化/XML 页面。示例标签有稳定 alias，需按实际项目规范调整。保存规范前检查与当前样本的时间/通道兼容性；发布后仍由后端按冻结规范独立验证全范围。

## 结果与完成

本地通用编辑器目前保存 LS 序列化数组：分类 choices、点/区间 timeserieslabels、备注等。新结果在后端采用何种版本化封装、如何保存原始 LS 字段、如何转换为平台语义，仍须按 14 号文档的 P0 样例冻结；不是将原始数组直接发送给只接受 labelId 的旧接口。

通用数值时间的标记采用实际轴值；timestamp 在当前 %Q 配置下往返为 Unix 毫秒字符串/数值。点要求起止相同；区间起止有序，均不得超出当前输入时间范围。通用曲线上的连续事件坐标不强制等于某个采样点，能耗小时桶另做领域语义校验。

当前编辑器几何区间端点与能耗业务 `[start,end)` 小时桶不等价。最后一个桶 `[23:00,次日00:00)` 的转换必须单独确定并验收，不能伪造第 25 个观测值，亦不能因绘图域结束于 23 就丢失合法业务结束边界。

草稿结构合法性与显式完成检查分开；后端仍检查领取、规范、样本及 revision。保留旧 image-classification-v1 和能耗试用格式，不原地重写旧结果。

## 导出及版本

当前本地 LS JSON 包使用同一通用输入适配，不再假设所有时序都有 energy payload。manifest 保留 inputFormat、schemaId、inputHash、时间类型/单位和通道名称/单位；XML 与结果按规范分目录。内联数据和引用 CSV 均须使用同一输入，不能残留 blob URL。

2026-11-14 已将 LS 配置解析/Converter 源码纳入后端，并实现本地 Python 改造、Java 调用与登录后的配置检查接口，详见 [源码接入进度](18-ls-source-adapter.md)。确认成果快照、原生结果存储及公共导出作业接口尚未接入，不能把独立转换测试或前端本地 JSON 包当成后端多格式导出业务已经完成。
