# 四人分工与验收（内部研发文档）

本文件不用于甲方产品展示。目标为2026年底跑通基本闭环、2027年1月实际试用；以四人投入和首期类型按时冻结为前提。

## 1. 职责与交付

| 人员 | 主要负责 | 交付物 | 交叉验收 |
|---|---|---|---|
| A：负责人/业务后端 | 项目创建准入、标注平台权限、任务席位、领取、提交 | 核心迁移与API、并发领取/回收、不可变提交 | C验收普通用户无审批发布及角色交互，B复核事务和约束 |
| B：数据后端 | 上传解析、样本ID、打包、结果导出、数据恢复 | 上传/解析job、固定打包计划、导出映射、恢复操作单 | D验证编辑器数据格式，A检查跨项目引用和导出权限 |
| C：产品前端 | 项目、任务广场、我的任务、结果页及标注入口 | 共用页面、状态提示、错误恢复、甲方演示路径 | A按真实API验收，D检查编辑器会话与保存状态 |
| D：编辑器/集成 | Label Studio固定版本、身份映射、模板、读回、隔离环境 | 接入验证记录、适配器、部署与回滚说明 | A共同负责权限；B协助存储备份；C负责入口联调 |

不要让D单独承包测试与运维。每人负责自身验证，两人交叉检查，最终四人共同走完整流程。成员姓名、技能和每周投入时长待确认；新成员没到岗时按实际人数重排。

## 2. 先对齐后并行

第一批共同冻结：一个真实任务模板、角色作用域、数据/包/领取/提交ID、API响应和错误码、N=2示例。C可用固定契约样例推进页面，但验收必须切到真实服务，不能用Mock代替成功证据。

A先交付项目/身份和领取契约；B与D用稳定sampleId、assignmentId对接；提交只能接受D成功同步后的版本。每周展示一个可操作增量，不等四人各自写完整套再集成。

## 3. 年底交付倒排计划（2026-11-03更新）

交付期限：2026-12-31之前完成第一版。内部验收目标提前到12月25日，12月28—31日仅用于交付缓冲，不安排新功能；2027年1月是实际使用与反馈，不承接首期必需功能的开发。

当前进度：产品、架构、数据库与接口设计稿已形成；新平台业务开发及生产部署尚未完成。以下全部为计划，不是已完成记录。

### 交付范围与投入条件

- 必须交付：自主建项、上传解析、标签规范、按包发布、自主领取、在线人工标注、草稿恢复、整包提交、需求方查看、带ID映射的导出、标注平台管理、权限隔离和持久化。
- 每包人数可设置，必须验收N=1和N=2；默认10样本/包并可配置，末包可不足10个。
- 首期至少冻结一个“数据格式＋标注任务＋标准导出”组合，不同时承诺全模态；复杂算法、结果融合、模型助手、自动超时回收、第二模态不进年底关键路径。
- 计划按四人自11月9日起持续投入估算，建议每人每周约30小时有效项目时间，其中约20%用于联调、评审和缺陷。11月6日前确认实际人员与投入；不足时立即重新估算并调整非核心范围，不降低权限与数据完整性标准。

### 四个必须守住的节点

1. **11月6日：范围与可行性冻结。** 若编辑器隔离无法验证，11月9日立即评审发行版/隔离方案和成本，不拖到12月。
2. **11月27日：完整流程贯通。** 不接受只有页面或只能单人保存的“完成”。
3. **12月4日：首期功能冻结。** 此后仅修缺陷、验收、部署；新增需求进入后续版本。
4. **12月25日：正式验收。** 剩余时间用于交付缓冲；不得把关键权限或数据问题带到明年。

### 完成定义

完成不等于代码写完：新平台在目标环境可用；普通用户自主发布；至少两名标注员对相同样本独立提交；需求方能查看并导出；权限、并发、恢复和原平台回归通过；交付源码版本说明、数据库迁移、配置模板、部署/回滚说明、操作手册、验收记录及备份恢复记录。上述部署与测试是后续实施任务，本轮不实际执行。

### 进度跟踪与延期处置

每周五演示本周完整增量，记录计划、实际、阻塞、责任人与预计解决日。接口/编辑器阻塞超过一个工作日升级给A协调；关键节点预计延误两天即重排，优先推迟第二模态、统计和便利功能，不删多人独立标注、授权、持久化与导出追溯。每周保留联调与修复时间，不能四人各自开发到最后一周才集成。

## 4. 内部兼容与部署约束

现有手动Demo只在本节作为运行兼容事项记录，不出现在甲方产品架构图。保留其版本、服务与数据，不以新平台替换其SQLite；新服务使用独立库、存储与路由。备份需包括源码差异、构建清单、配置模板、数据库一致性快照与上传文件，凭据另行受控保存。备份及恢复尚需实际执行，不能把写了计划当成已完成。

统一前端上线前回归原登录、训练入口与手动演示功能；服务器发布另行安排，不在文档任务中自动部署。不可把标注管理员映射为训练管理员，也不可为了标注平台禁用某人而直接禁用统一账号。

## 5. 验收清单与对应文档

| 验收场景 | 成功标准 |
|---|---|
| 角色作用域 | 标注管理员没有额外训练权限；训练管理员不自动获得标注管理权限 |
| 自主成为需求方 | 两个普通用户都无需管理员操作即可创建并发布自己的项目；仍可领取任务 |
| 项目隔离 | 普通用户不能管理、导出他人项目；管理员仅有约定的运维权限 |
| 打包 | 12样本按10个得到10/2，重试发布不重复生成；成员和规范冻结 |
| 多人席位 | N=1最后一席仅一人抢到；N=2两人成功，第三人失败，同人不能占两席 |
| 独立结果 | 同样本两人答案不同也分别保存，不互看、不覆盖、不产生假共识 |
| 草稿与提交 | 显式无目标可提交；未完成不能提交；旧revision拒绝；重试提交返回原ID |
| 回收竞态 | 回收和提交仅一种终态成功；回收后迟到写入失败；新领取不继承他人草稿 |
| 编辑器/文件权限 | 直接URL、任务ID、文件接口、导出接口均无法绕过领取范围 |
| 暂停/禁用 | 暂停后禁止工作数据访问及新写入；owner仍可管理历史结果；禁用仅影响标注平台 |
| 导出 | 只导出固定已提交清单，包含原始对应ID、人数完成状态，N=2不丢第二份 |
| 持久化 | 重启后已保存结果保留；任务失败可解释/重试；备份在隔离环境恢复成功 |
| 既有功能 | 登录、训练入口及现有演示不受影响 |

每项记录环境版本、账号、输入、操作、预期、实际和证据。容量验收指标（并发用户、项目样本量、单文件大小、响应时间、恢复时间）以真实需求确定，当前未给出性能保证。

## 6. 文档维护与评审结论

A负责总口径，B维护数据/导出契约，C维护页面与响应映射，D维护编辑器版本和权限证据。数据库字段变更同步接口文档；接口变更同步前端和验收样例。变更角色、可见范围、提交语义等必须更新产品说明，不能仅改代码。
