## 1. 目标、范围与当前基础

### 1.1 本轮目标

图片分类保留为已有能力与回归；本次增加能耗站点日插件，用它验证时序任务如何接入通用流程。能耗不是平台限定领域，其他任务应通过插件提供相应输入、编辑器、结果校验和导出适配。各模板共用以下流程：未标注数据导入 → 选择处理范围与人工/AI → 人工打包领取并整包提交，或 AI 批量执行并回传结果 → 需求方查看、修正和确认 → 选择全部或部分样本再次发布 → 最终确认 → 成果导出。

需求方始终决定业务流转；平台只提供推荐、筛选与算法建议。AI 自动标注必须实际执行，不以预留枚举、假结果或一次手工模型演示代替交付。

## 2. A 需要明确的设计问题及本轮答案

**最新执行规则（2026-11-09）：** 人工与 AI 使用不同的工作单位。人工领取 100 个包、每包 10 个样本时，按 100 个独立包分别处理和提交，6/10 只能保存草稿、10/10 才能提交。AI 可直接处理项目中选定的 1000 个样本，不需要先创建 100 个包；底层模型推理分批只是技术参数，不是人工任务包。

人工整包提交后，需求方可以挑选其中部分样本再次发布；如果交给人工，就组织为新的待领取包；整包重发可复用原包，子集需新包，并要求该范围全部完成；如果交给 AI，就生成固定样本范围的 AI 执行批次。

本轮实施默认：AI 逐样本持久化输出，执行批次结束时固定成功结果清单和失败/未完成清单。部分失败不阻止成功候选交给需求方查看、设阈值和确认；失败样本不伪造答案。批次运行中的进度不直接审核，先固定结果快照。模型失败与人工放弃不等于任务最终完成，只有需求方能确认成果。

### 2.1 功能默认值

以下是为减少反复讨论给出的实施默认值，属于本轮设计方案，不冒充老师逐条指定的要求。

| 问题 | 本轮答案 |
|---|---|
| 验收模板是什么？ | 图片分类作为既有模板与回归；增加energy-station-day时序模板，先2,000样例再全量23,177站点日 |
| 一包多少样本？ | 沿用可配置包大小，默认 10；10 是可调整默认值，不是固定要求 |
| 一轮分配几个执行者？ | 普通人工包默认1人；能耗质检范围采用2席位独立盲标，每人逐包完整提交。AI每次选一个Agent执行明确样本范围，不占人工领取席位 |
| 人工任务谁能看到？ | 当前部署内已登录且标注平台启用的用户可看任务摘要和领取；领取前不开放原图和结果。项目 owner 可领取自己的任务 |
| 是否另开匿名众包？ | 不开；不新增跨租户公开任务池。存在企业隔离时必须保留企业边界 |
| 人工选择如何提交？ | 发布时传 HUMAN_POOL，不传目标人工 actorId；领取时后端用当前身份建立 assignment |
| AI 如何选择？ | 在项目内选择样本或选择快照，再传 AI_AGENT 和 agentId；创建 AI 批次而非逐包领取记录，校验能力、规范和标签，不要求 packageId |
| 同一样本能同时交人工和 AI 吗？ | 本轮不允许重叠活动处理范围；按样本原子占用并在结束时释放。不同包或不相交 AI 批次可以并行，未来多人是同一人工轮次内多个授权执行者 |
| 什么叫本轮结束？ | 人工 assignment 已提交/释放/撤销，或 AI 批次终结并固定成功及失败清单；终结后迟到写入拒绝。已终结批次重试创建关联原批次的新 execution/round；执行内技术重试记录 attempt，不能改旧快照，关闭不等于审核通过 |
| 没人领取怎么办？ | owner 可撤销尚未领取的轮次，再创建新轮次，不直接修改已发布内容 |
| 人工允许部分或 0 张结果提交吗？ | 不允许；可以保存部分草稿，或释放/撤销执行，但不生成正式 submission |
| AI 部分失败如何处理？ | 固定本批已成功的有效候选和失败清单；owner 可审核成功项，决定重试失败项或把它们打包发人工。AI 不调用人工整包 submission 接口 |
| 人工完整提交保存什么？ | 冻结当前包本轮范围内全部已完成样本的结果版本；缺一项、重复或混入包外/轮次外样本均拒绝 |
| 领取 100 个包怎么提交？ | 每个包每轮每名领取者对应一条 assignment，每包独立校验、独立提交；完成一个就可提交一个，不等待其他 99 个包，也不把它们合成一次提交 |
| 部分样本再次发布怎么算整包？ | 需求方选出的样本构成本轮冻结的处理范围，领取者必须完成该范围全部样本；原包未纳入本轮的样本无需重复处理 |
| 引用结果会自动算本轮完成吗？ | 不会；参考答案和本轮显式完成分开。人工需确认当前样本完成后才计入本轮结果 |

| 默认参考什么？ | 存在 owner 当前选定的候选结果时预填其版本引用，并让发布者预览；无选定结果或多份答案有歧义时不猜选，显示需要选择 |
| 已确认样本再次发布怎么办？ | 先提示影响；发布成功时将选中样本的当前审核状态重置为待审核，保留旧确认历史。未选样本不变 |
| 什么时候成果完成？ | 人工包或 AI 处理范围均由 owner 主动确认，要求固定成果范围内全部样本有有效已确认结果且无活动执行；未打包 AI 样本也能形成成果，不为导出强制打包。缺项返回清单 |
| 完成后能再打开吗？ | 本轮完成后只读；后续重开另做显式操作，不能靠草稿保存偷偷重开 |

| 无人领取自动过期吗？ | 首轮不做自动过期；已有手动释放、撤销流程可复用，owner 可处理阻塞 |
| 推荐是否自动执行？ | 不执行；筛选、预选、数量提示只帮助决策，发布与审核都需用户点击确认 |

### 2.2 标识、数据归属与状态

所有业务 ID 用 UUID 字符串，时间传 ISO 8601 UTC；identityUserId 沿用统一身份的原始字符串。前端不依赖 UUID 内部含义。actor.kind 沿用已有 HUMAN / MODEL：AiAgent 对应 MODEL，不额外引入一套 AI 身份枚举。

| 对象 | 关键关联与要求 |
|---|---|
| Project | ownerActorId；不修改训练角色 |
| Sample | projectId、batchId、sourcePath、内容摘要；原始内容只读 |
| TaskPackage | 人工工作单位，projectId、specVersionId、固定成员清单；AI 执行不要求存在此对象 |
| PublicationRound | projectId、specVersionId、mode、任务要求、revision、状态；人工轮次关联 packageId，AI 轮次无需 packageId，范围由 RoundItem 固定 |
| RoundItem | roundId、sampleId、可空的 referenceResultId；属于本项目及本轮规范，人工额外检查包成员；引用结果对应同一样本和规范 |
| Assignment | 人工领取记录，roundId、packageId、actorId、状态、revision；同一 actor 在同一轮不得重复占位 |
| ResultRevision | 来源明确为人工 submissionId（可追溯 assignmentId）、AI executionId、owner 修订或 aggregationId；sampleId、规范、内容、revision、来源引用。来源互斥且校验归属，统一结果内容但不强制 AI 绑定人工 assignment |
| AI Execution | roundId、agentId（MODEL actor）、modelVersion、attempt、固定样本范围、执行状态；无需 assignmentId/packageId，终结时产生成功结果快照和失败清单 |
| ReviewDecision | sampleId、targetResultId、owner、动作、原因、审核 revision；确认具体答案，不只确认 sampleId |
| ConfidencePolicy | AI 执行结果快照、modelVersion、lowerThreshold、upperThreshold、revision |
| AggregationRun | 输入样本与结果快照、算法版本、参数、输出；不伪装成人或 AI 的原始提交 |
| FinalSnapshot | projectId、固定样本范围、已确认结果 ID 清单、规范、文件映射、创建者；包关联可选，支持没有人工包的 AI 成果导出 |

不要给一个 sample 只存唯一 marks，也不要把最后一次写入直接当最终答案。列表可以维护当前选择结果的引用，但历史版本不得覆盖。

状态分成执行和审核两条轴：

- 包运行状态沿用 OPEN / PAUSED / CLOSED；最终成果用独立审核快照表示，不把已提交人数等同审核完成。
- 发布轮次建议使用 OPEN / CLOSED / CANCELLED；人工和 AI 各自结束后由需求方决定下一步，不自行创建新轮次。
- 人工 assignment 沿用 CLAIMED / IN_PROGRESS / SUBMITTED / RELEASED / REVOKED。SUBMITTED 表示“本包本轮全部完成并已提交”，仍不代表需求方审核通过。
- AI 执行使用 QUEUED / RUNNING / SUCCEEDED / PARTIAL / FAILED / CANCELLED；D 执行、A 管理批次及结果收尾。PARTIAL 表示成功和失败并存，成功候选冻结后可审核；FAILED 无成功候选。取消时固定已产生的有效结果并拒绝迟到写入。无需人工 submission，也不要求全批成功后才能保留和审核成功候选。
- 当前结果审核使用 UNREVIEWED / PENDING / NEEDS_REVISION / ACCEPTED；无结果时 hasResult=false。低置信度不会自动改成 NEEDS_REVISION。
- “已确认”针对指定结果版本；旧版本确认不自动传递给新答案。NEEDS_REVISION 只能由 owner 的明确操作设置。

### 2.3 置信度与批量审核的确定规则

1. AI 交回后先展示结果、模型版本、执行情况和分数分布；未设阈值时不显示系统认定的高低分档。
2. 首个分类模板每条结果至多一个该预测类别的 confidence，允许 null。适配器只接受语义明确、范围为 [0,1] 的分数；百分比分数必须按该模型已知定义转换，不猜测或虚构。
3. 需求方手动设置 L、H，校验 0 ≤ L < H ≤ 1；低分 c < L，中分 L ≤ c < H，高分 c ≥ H。未知分数单列 UNKNOWN。
4. 阈值绑定一轮中选定的 AI 执行结果快照和模型版本，不混用不同模型或不同执行版本；数字 0.60、0.90 只是说明示例，界面不得偷偷应用为审核默认值。
5. C 提供预览和排除个别样本；批量确认请求提交明确的结果 ID、样本 ID、审核 revision、阈值 policyId。A 重查归属、版本与阈值，不接受只有“确认所有高分”这种不固定范围的写入。
6. 分页查询必须支持“只选本页”与“全部筛选结果”区别。全部筛选先形成后端选择快照，再预览和确认，不能把当前页误当全部。
7. 本轮批量确认遇到任一过期或非法对象整体拒绝并提示刷新，不部分成功却显示全成功；限制单次明确 ID 数量，超大批次由可追踪作业后续承接。
8. 改阈值只改变分档，不自动修改以前审核记录。任务最终完成仍需 owner 单独确认。
9. 中、低、未知组都由 owner 决定逐条检查、修改、确认、标记待修正或再次发布，不自动路由。
10. 多数投票支持比例不是模型 confidence，单独展示 voteCount / validVoteCount，不能套用模型阈值。

### 2.4 接入与接口共识

沿用 /api/labeling/v1、统一 ApiResponse、requestId、Bearer 身份校验和错误结构。文件、草稿、审核、导出每次都检查后端权限。AI 工作线程使用受限内部执行身份，不把 owner Token 或模型密钥交给浏览器。

业务状态变更使用 Idempotency-Key；草稿、审核和发布使用 revision 防止旧页面覆盖。相同键相同内容返回同一操作结果，相同键不同内容返回 409。所有结果范围跨项目、跨轮必须拒绝；人工另校验包成员，AI 按固定执行范围校验，不人为套用包边界。

## 10. 共同验收用例

### 10.1 一条必须跑通的真实业务流程

1. 需求方上传 20 张未标注图片，设置与真实模型兼容的标签；先不创建人工包，所有初始答案为空。
2. 直接选定 20 张交给 AI，创建一个无 packageId 的 execution，真实执行并固定结果快照，带模型版本和可空置信度。单独注入失败验证 PARTIAL 时成功候选仍可审核，模拟异常不代替真实模型调用。
3. owner 先看结果，再手动设置 L/H。设阈值前后审核状态均不自动改变。
4. owner 预览选中范围并排除一项，点击批量确认；核对确认数量和具体版本。
5. 对其余结果标记待修正或直接选择再发布；选择 HUMAN_POOL 后按配置打包，携带明确 AI 结果引用，再进入任务广场。
6. 普通标注员在任务广场领取，只能查看本轮范围；先保存部分样本并尝试提交，必须被拒绝；完成本轮全部样本后才能正式提交。
7. owner 查看完整提交、确认正确项，对仍需修正的部分再发布；本轮选定 4 张时必须完成这 4 张，不重复要求其他已确认样本，新轮次不覆盖旧答案。
8. owner 所有样本确认后结束任务包；缺任何样本或有活动轮次时完成操作必须失败并给出原因。
9. 导出成果，CSV 每条结果都能对应原图、标签及审核记录。结果列表与导出数量一致。
10. 另用人工先处理并整包提交，再跨已提交包选取样本交给同一 AI 批次，证明 AI 不受人工包边界限制；另验证全部 AI 成果无需创建人工包也可确认导出。
