# 团队协作与验收清单

更新：2026-11-20。合并原 05、13 的职责和验收约定，以及 07 的交付规则。本文说明谁负责、如何对接和怎样验收；业务规则查 [产品说明](01-product.md)，字段查 [接口契约](04-api.md)，完成状态查 [STATUS.md](09-status.md)。旧日期排期保留在归档，不作为新的工期承诺。

## 1. 职责与交付

| 角色 | 主责 | 必须交付 |
|---|---|---|
| A：负责人和业务后端 | 权限、项目/规范、发布/领取、草稿提交、AI 生命周期、审核/成果、插件核心与迁移 | 可调用接口、约束和错误示例、迁移兼容证据、跨模块验收 |
| B：数据与算法后端 | 导入/授权读取、查询分页/统计、固定选择范围、集成建议、导出 | 真实样本响应、源映射、插件导入/导出、筛选数量一致性证据 |
| C：平台前端 | 项目/数据/发布、任务广场/我的任务、核查/重标、成果/导出 | 真实 API 流程、可信插件和编辑器装配、错误/冲突/只读反馈 |
| D：编辑器与 AI | 编辑器/结果转换、领域完成规则、Worker 和真实模型/规则执行 | 组件使用说明、校验正反例、模型版本/标签映射/分数定义、真实执行证据 |

每位成员负责自己模块的权限、异常处理和验证记录。A 协调共享迁移、统一结果服务及跨模块接口；C 负责宿主，D 负责编辑器内部，不再各自维护另一套答案存储。

## 2. 按依赖对接

| 工作场景 | 先给出什么 | 接收方 | 对接完成的判断 |

| 图片导入与浏览 | B 给导入/列表/原图接口示例 | C、D | C 能浏览；D 能在授权上下文读图 |
| 发布与领取 | A 给人工包、AI 范围、轮次和领取契约 | B、C、D | C 可配置发布；B/D 能按固定范围处理 |
| 编辑器保存 | D 给组件协议；A 给草稿接口 | C | C 能保存、恢复、展示冲突；后端保留唯一答案 |
| 人工提交 | A 给 assignment 包成员与提交接口 | C、D | 单包完整可提交；未完成包只能保存；其他包不阻塞 |
| AI 执行 | A 给 execution 授权和生命周期；D 给可信模型输出 | B、C | B 可统计；C 可显示；成功和失败列表可追溯 |
| 置信度审核 | D 给置信度语义；A 存策略和审核；B 做统计/选择；C 做界面 | A、B、C、D | 手动设阈值、固定范围、显式确认，状态变化可查 |

| 成果导出 | A 固定 finalSnapshot；B 生成导出；C 展示状态 | A、B、C | 导出只含快照中已确认结果，且可对应原图 |

共享数据库迁移和统一结果服务由 A 协调。B/D 需要新增共享字段时，先提交字段名、含义、约束、读写方和迁移影响，不要同时修改同一迁移文件。C 的前端权限控制只负责交互体验，不能代替后端授权。

## 3. 开发与交付规则

1. 开始编码前，各成员先确认自己负责的接口和字段；有冲突先在团队同步，由 A 更新 `04-api.md` 或本文件，再并行实现。
2. 每个成员在自己的功能分支提交代码并创建 PR；PR 描述写明功能、接口变化、迁移、验证步骤和未完成项。不要直接提交到共享目标分支或覆盖他人工作。
3. 先合并兼容的接口/实体，再合并依赖它的页面和模型适配。迁移必须能说明旧数据如何处理；不得通过重置共享数据库掩盖迁移问题。
4. Mock 可以帮助前后端并行，但页面和交付说明必须标明 Mock；阶段验收以真实 API、真实数据和真实模型执行证据为准。
5. 遇到阻塞时说明：阻塞点、已尝试内容、需要谁提供什么、是否影响其他人的任务。接口变动时通知所有调用方并同步文档。
6. 交付时提供：代码分支/PR、运行配置说明（不含密钥）、关键操作步骤、验证证据、剩余问题和依赖项。

- 前后端继续在现有 Trunk 工作区开发，先核对实际 Git 根目录、分支和工作区；团队 PR 目标以仓库约定为准，不盲目推送覆盖共享分支。
- 提交只包含本次相关源码、迁移和文档，不包含凭据、业务数据、日志及构建产物。由用户手动 git add/commit，不自动提交。
- 图片导入调用约定已合入 [接口契约第3节](04-api.md)；插件实现步骤已合入 [插件开发](08-task-plugins.md)。

## 4. 共同验收流程

1. 需求方创建项目并选择插件，上传一份未标注图片数据，确认样本 ID 稳定且外部标签未被导入。
2. 配置分类标签，选择人工或 AI。
3. 人工路径：创建多个包并自行领取；完成一个包的全部样本后提交；未完成包保存草稿；已完成包不等待其他包。
4. AI 路径：选择 Agent 和样本范围；真实运行；结束后固定成功结果与失败清单；成功结果可先交需求方处理。
5. 需求方查看来源和结果，手动设置 AI 置信度阈值，预览后显式确认；确认不能由阈值自动触发。
6. 需求方挑选全部或部分样本再次发布，确认人工包重新组织或 AI 直接执行，并能追溯上一版结果。
7. 需求方确认固定范围的最终成果；缺项或活动执行时不能完成；导出结果能映射回原始样本。

验收记录按实际结果填写“通过 / 未通过 / 阻塞”，附请求、页面截图或日志。设计完成、接口写好、Mock 显示成功都不能单独记为端到端通过。

## 5. 分项验收矩阵

| 用例 | 必须满足 | 主责/复核 |
|---|---|---|
| 角色隔离 | 普通用户自主建项；标注管理员不改变训练角色；普通标注员不能调用 owner 审核 | A / C |
| 样本归属 | 跨项目、包外、轮次外 ID 全部拒绝；猜到文件 URL 不能绕过权限 | A+B / D |
| 并发领取 | 单席位只成功一次，同人重试不重复占位 | A / B |
| 按包提交与草稿 | 10 张完成 6 张只可保存不能提交，补齐后成功；空提交拒绝；多个包独立提交；旧 revision 和迟到写入拒绝；参考结果不算完成 | A+D / C |
| 分档边界 | 等于 H 归高、等于 L 归中、null 归未知；L≥H 拒绝 | A+B / C |
| 批量确认 | 预览与实际范围一致，版本变化整体拒绝，不因改阈值改变旧确认 | A+B / C |
| 待修正来源 | 只有 owner 明确标记产生 NEEDS_REVISION；低分不自动产生该状态 | A / C |
| 再次发布 | 只处理选中样本；保存参考版本；已确认样本重发需明确提示并重置当前审核 | A+C / B |
| AI 真实执行 | 有真实模型、权重版本、输入输出证据；Mock 不算通过 | D / A |
| AI 范围与故障 | 无人工包也可执行；PARTIAL 的有效成功候选可供 owner 审核，失败无答案；范围外、迟到、重复结果拒绝；转人工须打包；无包成果也可导出 | D+A / B |
| 编辑器边界 | 完整 LS 服务未部署启动也可保存、恢复；主链路不调用 LS 项目任务 API | D+C / A |
| 多数投票 | 2/3 形成建议，1/2 不形成严格多数，少于两票提示不足；派生或重复答案不自动多计 | B / A |
| 完成与导出 | 只导出明确已确认快照；任务进入成果列表而非删除；原图映射可回读 | A+B / C |
| 重启恢复 | 领取、队列、草稿、结果、审核持久化；AI 工作恢复不重复写答案 | 各模块 / A统筹 |
| 旧平台 | 统一登录、平台选择和训练入口回归；独立标注存储不污染其他服务 | C+A / B |

验收记录包括代码版本、环境、操作账号、输入、预期、实际结果和证据。源码静态检查、单元测试、Mock 联调、真实模型联调、服务器部署分别记录，不互相替代。

## 6. 插件与能耗增补验收

除图片回归外，验证精确插件版本、未就绪禁止创建、历史版本不回退、在途批次不随升级改变、跨项目读取拒绝、结果格式及完成规则、冻结成果导出。能耗样例使用真实 2,000 条数据；全量历史资产、金标准、双标及一致性指标按 [能耗需求](07-energy-requirements.md) 分别验收，不合并为一个“已完成”。

## 7. 证据记录

每次记录代码版本（包含是否有未提交修改）、环境/依赖、账号与数据范围、操作、预期、实际结果及证据位置。测试通过、跳过、阻塞分别计数；Mock、接口、浏览器、真实模型、部署核验分别记录。最新摘要只更新 [STATUS.md](09-status.md)，历史报告放入 archive，不复制测试数量到每份主文档。
