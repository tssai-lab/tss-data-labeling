# 人工与多 Agent 联合发布：实现约束

状态：本地实现及测试中，尚未部署。本文基于 backend `b6fdc02764f3c39bc8886f8f5affaf4895e93832`，接口细节见 `04-api.md`；不能将这些内容当作服务器已上线接口。

## 当前限制

- `sample_work_claim` 的主键为 `(project_id, sample_id)`；每个人工包和 AI 执行创建不同轮次，当前不能共同占用同一样本。
- `TaskService.publish` 与 `AiService.createExecution` 分别检查占用并写入占用记录，均在自己的事务中重置已确认状态。直接连续调用会遇到 `SAMPLE_BUSY`，也可能产生部分发布。
- `result_selection` 固定样本、结果和审核版本，消费时重新检查范围、审核状态和占用。用户搜索和本地选择不应被当成已冻结范围。
- `/agents?taskType=...` 只返回启用且任务类型匹配的 Agent；发布时仍须检查 Agent、规范与实际执行能力，不应把设计示例中的模型名称当作已注册或可用。

## 联合发布约束

1. 建立单个发布批次，冻结项目、规范、PUBLISH selection、选择摘要、人工配置和去重后的 Agent 列表；展示确认页前读取固定范围，确认时重校验过期、权限、版本、样本输入和审核 revision。
2. 同一个发布批次允许一份人工包组和每个 Agent 的独立执行共享样本；其他发布批次仍应收到 `SAMPLE_BUSY`。需要数据模型明确区分批次级占用与批次内来源成员，并保留旧记录及兼容的历史查询。
3. 同一事务中加锁并执行所有校验，原子创建人工任务包、各 Agent 执行、成员和来源信息；全部失败回滚。相同幂等键和相同请求重放原回执，键重复但请求不同须报冲突。
4. 纳入已确认样本时，只有用户明确同意才重置确认状态；整个批次对每个样本仅执行一次重置和审计。固定快照不得被后续选择、结果或规范变更改写。
5. 每个来源独立记录执行与失败，取消、完成、重试只释放该来源；批次的样本占用仅在全部来源终结后释放。独立重试也必须遵守幂等、输入版本和权限校验。
6. 结果需保留提交人或 Agent、executionId、resultId 和规范版本，核查页按来源选择，多个候选不得按时间猜测已确认答案；最终成果仍使用现有结果选择和 revision 校验。

## 验收建议

覆盖人工加两个 Agent 的同范围成功、外部批次冲突、不可用 Agent、权限和规范不匹配、部分创建失败的原子回滚、幂等重放、并发请求竞争、已确认样本重开、单个来源失败或取消、独立重试、全部来源结束才释放占用、结果按来源查询以及旧单来源 API 兼容。
