# LS 风格工作区布局收尾

日期：2026-11-15。本地 `feat/frontend_LS`，未推送、合并或部署。

本轮参照 LS DataManager 的任务表与标注工作区组织方式。列表继续连接平台项目、任务包和审核 API；编辑器使用仓库内 LS 1.23.2 源码。没有更改结果格式、保存接口或绘图控件。

## 页面变化

| 页面 | 当前组织 |
| --- | --- |
| 项目数据管理 | 紧凑项目／规范工具栏，样本表为主体；搜索、审核状态筛选、复选、所选计数和发布入口集中在表上方 |
| 样本预览 | 从样本表直接打开只读侧栏，可连续上一条／下一条；按当前选择的规范预览，修复此前总用最新规范的问题 |
| 导入 | 保留侧栏上传及按需生成任务，主列表不铺开字段映射表单；缺少规范时说明为何暂不能预览／发布 |
| 标注 | 进入专注工作区，收起平台侧导航；顶部只保留返回、样本选择、上一条／下一条、包进度和说明／刷新／释放 |
| 任务包列表 | 按需打开可搜索的样本侧栏，显示每条的待标注／草稿／完成状态 |
| 编辑区 | LS 原生数据对象、标注控件、区域／关系面板、历史与工具；减少外围重复的样本标题和实现说明 |
| 保存 | 同一栏提供保存草稿、标记完成、整包提交，保持三种业务语义；全包未完成时提交不可用，单次保存中也不能重复提交 |
| 参考结果 | 切到原规范只读查看，再返回当前编辑；不同时挂载两个编辑器，不把参考自动计为完成 |
| 已提交／核查 | 只读提交页同样压缩顶部、按样本查看；核查编辑区采用一致的紧凑容器，保留确认／修订业务操作 |

批量发布复用现有发布计划：表格所选样本带到发布页，再确认规范、包大小和范围；未跳过原来的发布确认和后端校验。

## 原生样式边界修复

`vendor/label-studio/libs/ui/src/lib/Tooltip/Tooltip.tsx` 原本固定把提示挂到 `document.body`。编辑器样式位于 Shadow DOM，导致提示失去样式、文字落到页面底部。本次让 Shadow DOM 内的提示挂回同一个根，并按实际定位父节点换算坐标；普通文档中的行为保持原样。设置弹窗、提示位置及样式已经过浏览器操作检查。

开发服务会保留编辑器静态资源的缓存；重建 `public/ls-editor` 后，本次已重启本地前端使资源生效。已打开的页面需刷新，不能仅凭热更新判断编辑器源码已更新。

## 验收

可复跑脚本：`node scripts/qa/ls-workspace-layout-browser.cjs`。脚本生成自身的两样本 ZIP 测试数据，仅访问 localhost。可用 `LS_TEST_USERNAME`／`LS_TEST_PASSWORD` 指定本地账号。

已通过：

- 不同规范下的正确预览、预览上一条／下一条、表格复选与发布范围带入。
- 1280／1700 两种宽度下，原生编辑区顶部约210px、宽1222／1642px，页面无横向溢出。
- 原生设置与提示、任务包侧栏搜索、未保存时取消切换、草稿保存后切换与恢复。
- 单样本完成与整包提交分开；保存栏无重复操作；提交后原始结果只读。
- 真实页面重新完成两样本时序标注、整包交回、需求方确认、项目完成与实际 JSON 下载。
- 图像 CSV 引用资源、生成任务、发布领取、原生画框保存；跨规范成果选择与分组下载。

类型检查、编辑器源码构建、整站生产构建分别记录在工作区 `.tools/ls-layout-types.log`、`ls-layout-editor-build.log`、`ls-layout-production-build.log`。浏览器证据为 `.tools/native-tests/ls-layout-regression.json`、`ls-focused-1280.png`、`ls-focused-1700.png` 和相关流程日志。
